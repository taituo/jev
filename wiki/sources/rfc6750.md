# RFC 6750 — Bearer Token Usage

RFC 6750 defines how bearer tokens are presented to resource servers;
any party in possession of the token can use it (RFC 6750 §1).

## Three transmission methods

- Clients MUST NOT use more than one transmission method per request
  (RFC 6750 §2).
- Authorization header with the `Bearer` scheme is the RECOMMENDED
  method; resource servers MUST support it (RFC 6750 §2.1).
- Form-encoded body uses the `access_token` parameter under strict
  content-type and single-part conditions (RFC 6750 §2.2).
- URI query uses the `access_token` parameter but is NOT RECOMMENDED
  because URLs are logged and cached (RFC 6750 §2.3).

## Errors and protection

- The `WWW-Authenticate` header carries bearer error information
  (RFC 6750 §3).
- Defined error codes include `invalid_request`, `invalid_token`, and
  `insufficient_scope` (RFC 6750 §3.1).
- Bearer tokens MUST be protected with TLS; without it any holder can
  impersonate the client (RFC 6750 §5.1, RFC 6750 §5.2).
