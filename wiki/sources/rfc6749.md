# RFC 6749 — The OAuth 2.0 Authorization Framework

RFC 6749 defines four roles: resource owner, resource server, client,
and authorization server (RFC 6749 §1.1). The abstract protocol flow
covers authorization grant, token issuance, and protected-resource
access (RFC 6749 §1.2).

## Grants

- Authorization code, implicit, resource-owner password credentials,
  and client credentials are the four grants (RFC 6749 §1.3).
- Authorization code is a two-step redirection plus token exchange flow
  (RFC 6749 §4.1).
- Implicit issues tokens directly from the authorization endpoint
  (RFC 6749 §4.2).
- Resource-owner password credentials exchange a username and password
  for a token (RFC 6749 §4.3).
- Client credentials use the client's own credentials (RFC 6749 §4.4).

## Tokens and endpoints

- Access tokens denote scope, lifetime, and access attributes
  (RFC 6749 §1.4).
- Refresh tokens can obtain new access tokens without re-authorization
  (RFC 6749 §1.5).
- The authorization endpoint handles authorization; the token endpoint
  issues tokens (RFC 6749 §3.1, RFC 6749 §3.2).
- Successful token responses and error responses have distinct formats
  (RFC 6749 §5.1, RFC 6749 §5.2).
- Refreshing an access token uses the `refresh_token` grant
  (RFC 6749 §6).
