# RFC 7515 — JSON Web Signature (JWS)

RFC 7515 defines JWS for digitally signing or MACing content with a
JSON-based JOSE header (RFC 7515 §1).

## Header parameters

- `alg` identifies the cryptographic algorithm; it MUST be present and
  MUST be understood and processed (RFC 7515 §4.1.1).
- `jku` is a URI to a JWK Set for the signing key; retrieval MUST use
  integrity-protected transport (RFC 7515 §4.1.2).
- `kid` is a key identifier used as a hint for key selection
  (RFC 7515 §4.1.4).
- `typ` declares the type of the object; `cty` declares the media type
  of the secured payload (RFC 7515 §4.1.9, RFC 7515 §4.1.10).
- `crit` lists extension header parameters that MUST be understood and
  processed (RFC 7515 §4.1.11).

## Producing and consuming

- Signature/MAC computation and validation procedures are defined
  separately; validation failure means the JWS is invalid
  (RFC 7515 §5.1, RFC 7515 §5.2).
- Algorithm acceptance remains an application decision; a valid JWS with
  an unacceptable algorithm SHOULD be treated as invalid
  (RFC 7515 §5.2).

## Serializations

- JWS Compact Serialization is three base64url parts joined by periods:
  protected header, payload, signature (RFC 7515 §7.1).
- JWS JSON Serialization supports multiple signatures; the general form
  and the flattened form are defined separately (RFC 7515 §7.2.1,
  RFC 7515 §7.2.2).
